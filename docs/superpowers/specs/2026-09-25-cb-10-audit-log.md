# CB-10 Audit log — design note (bounded)

Issue: #10. Blocked-by: CB-03 (closed).

## Acceptance criteria (issue body)

Every tool call (read + write) logged to `audit_log(id, tool_name, params, result, timestamp, dry_run_flag)`.
`get_audit_log(start_time?, end_time?)` read tool to retrieve history.

## Scope decisions

- **Column naming**: CB-03 already created `audit_log(id, tool_name, called_at, env, request, response)`.
  Keep those names; the issue's `timestamp`/`params`/`result` are informal aliases for the same
  concepts, not a literal rename mandate. Renaming would touch already-merged schema and the
  audit-write code CB-06 built in its own unmerged worktree for no behavioral gain.
- **Missing column**: `dry_run_flag` genuinely does not exist yet. Added via
  `V3__audit_log_dry_run_flag.sql` — renumbered from the originally-planned `V2` after CB-04's
  `V2__seed_products.sql` merged first, an expected shared-file collision like `Server.scala`/
  `build.sbt`.
- **Parallel-lane collision**: CB-06 (unmerged, its own worktree) already built `db/Db.scala`
  (magnum `Transactor`) and `tools/AuditLog.scala` (`record(...)`) for its own write path. CB-10
  builds the same shapes independently now; whichever of the two stories rebases onto `main` second
  reconciles the duplicate files, same as any other shared-file conflict this workflow expects.
- **Excluded**: write-tool business logic (CB-06/07/08's job), connection pooling, and a
  validation/error-code framework for malformed `start_time`/`end_time` strings (CB-19's job —
  invalid input just fails naturally here).

## Components

- **`db/Db.scala`**: `Db.transactor(config: DbConfig): Transactor` — `PGSimpleDataSource`, no
  pooling (single-writer mock server).
- **`tools/AuditLog.scala`**: `AuditLog.record(xa, toolName, env, requestJson, responseJson,
  dryRun): Unit` — one `INSERT INTO audit_log(tool_name, env, request, response, dry_run_flag)` in
  its own always-committed transaction, independent of whatever transaction (if any) the caller's
  own work ran in, so a dry-run rollback can never take its own audit row with it.
- **`tools/GetAuditLog.scala`**: pure-ish query object taking a `Transactor`, optional
  `startTime`/`endTime` (`java.time.OffsetDateTime`, parsed from ISO-8601 strings), returns matching
  rows ordered by `called_at` as a JSON-encodable list. Reads `system_clock`? No — audit history is
  bounded by caller-supplied timestamps, not the mock clock.
- **`Server.scala`**: adds `private val xa: Transactor = Db.transactor(DbConfig.fromEnv())`
  (construction is lazy-connect — building it cannot break the existing CORE_ENV guard tests, which
  never reach a tool call). Wraps `ping` to call `AuditLog.record` after building its response.
  Registers `get_audit_log(startTime: Option[String], endTime: Option[String]): String`, itself
  logged the same way after it builds its response.

## Test-plan note

`ServerProcessSpec`'s happy-path `spawn` currently clears the child process env down to
`CORE_ENV=sandbox` only. Since `ping` now needs `DbConfig.fromEnv()` to reach Postgres, the spawn
call must also forward `DATABASE_URL`/`POSTGRES_USER`/`POSTGRES_PASSWORD` from the running test
JVM's `sys.env`, matching the same ambient-env convention `SchemaMigrationSpec`/`DbConfigSpec`
already use.
